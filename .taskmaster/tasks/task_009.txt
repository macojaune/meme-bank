# Task ID: 9
# Title: Frontend Video Display, Search, and Browsing UI
# Status: pending
# Dependencies: 4, 8
# Priority: high
# Description: Build the frontend user interface for browsing video categories, displaying video lists, implementing the search bar, showing search results, and providing a video playback interface. Integrate with the backend search and browsing APIs.
# Details:
Create React components for a video grid/list display, a search input field, category filters, and a video player component (e.g., using the HTML5 video tag or a library like ReactPlayer). Fetch data from the backend `/browse` and `/search` endpoints and render the results. Implement pagination or infinite scrolling if necessary.

# Test Strategy:
Manually test browsing different categories and applying filters. Use the search bar with various queries and verify that relevant results are displayed. Ensure videos play correctly in the integrated player.

# Subtasks:
## 1. Implement Core Layout and Initial Video List Display [pending]
### Dependencies: None
### Description: Create the main page layout components (e.g., header, main content area). Develop reusable React components for displaying a single video item (e.g., `VideoCard`) and a list/grid of video items (`VideoList`). Fetch initial video data (e.g., a default browse category or recent videos) from the backend `/browse` endpoint upon component mount and display it using the `VideoList` component.
### Details:
Use React functional components and hooks for state management and data fetching. Implement basic styling for the layout and video cards. Handle loading and error states for the initial data fetch.

## 2. Add Category Navigation and Filtering [pending]
### Dependencies: 9.1
### Description: Develop a component for displaying video categories (e.g., `CategoryFilter` or navigation links). Implement logic to fetch available categories (if provided by the API) or use a predefined list. When a category is selected, trigger a new API call to the `/browse` endpoint with the selected category ID/slug and update the `VideoList` display with the results.
### Details:
Integrate the category component into the main layout. Use state to track the currently selected category. Update the data fetching logic to include the category parameter in the `/browse` API call. Consider how to visually indicate the active category.

## 3. Implement Search Bar Component [pending]
### Dependencies: 9.1
### Description: Create a `SearchBar` React component containing an input field and potentially a search button. Implement state management within the component to track the user's input query. Add event handlers for input changes and triggering a search action (e.g., on button click or 'Enter' key press).
### Details:
Place the `SearchBar` component in the main page layout, typically in the header. Use controlled components for the input field. The search action should ideally trigger a function passed down from a parent component.

## 4. Integrate Search API and Display Search Results [pending]
### Dependencies: 9.1, 9.3
### Description: Connect the search action from the `SearchBar` (Subtask 3) to call the backend `/search` API with the user's query. Modify the main page logic to handle the response from the `/search` API. Implement logic to switch the display in the main content area between the browse results (from Subtask 1/2) and the search results based on whether a search has been performed and results are available. Reuse the `VideoList` component to display search results.
### Details:
Manage state in a parent component to hold both browse and search results, and a flag indicating whether search results should be shown. Implement the API call to `/search`. Handle cases with no search results. Consider clearing search results when the search bar is cleared or a category is selected.

## 5. Implement Video Playback Interface [pending]
### Dependencies: 9.4
### Description: Create a `VideoPlayer` React component, potentially using the HTML5 `<video>` tag or a library like ReactPlayer. Implement logic so that when a user clicks on a `VideoCard` (in either browse or search results), the `VideoPlayer` component is displayed, hiding the list view, and starts playing the selected video using its source URL.
### Details:
Add state to the main page component to track which video (if any) is currently selected for playback. Conditionally render the `VideoPlayer` component based on this state. Pass the selected video's source URL to the `VideoPlayer`. Implement a way to close the player and return to the list view (e.g., a close button).
